# 答讯 · ReplyNotice — v2.0.0 需求文档

## 一、基本信息

- 项目仓库：`LynFrost/Daxun`
- 原插件名称：ChatGPT Notifier
- 目标中文名称：答讯
- 目标英文名称：ReplyNotice
- 目标展示名称：**答讯 · ReplyNotice**
- 当前版本：v1.5.0
- 目标版本：**v2.0.0**
- 开发分支：`feature/v2.0.0`

## 二、需求

### 1. 增加新名称

将浏览器扩展向用户展示的名称修改为 **答讯 · ReplyNotice**。

**验收标准：** 扩展管理页面显示“答讯 · ReplyNotice”。只调整所需展示名称，不额外修改代码内部标识、仓库名称或其他功能。

### 2. 版本升级至 v2.0.0

将当前插件版本由 **v1.5.0** 升级为 **v2.0.0**，确保扩展清单、插件面板等现有版本显示保持一致。

**验收标准：** 扩展清单版本字段为 `2.0.0`，面板对用户显示 `v2.0.0`。

### 3. 修复 ChatGPT 回答完成后的 Windows 系统通知

**问题现状：** 当前 v1.5.0 在 ChatGPT 回答完成后，Windows 系统通知未能可靠弹出。Windows 通知总开关已开启，但尚未定位到唯一故障环节，不能直接认定是某一个 DOM 选择器或通知 API 导致。

**目标行为：** 在 Edge 中使用 ChatGPT 时，若插件面板的 System Notification 已启用、浏览器和 Windows 允许通知，则**每轮 ChatGPT 回答最终完成时发送且仅发送一次系统通知**；不要求更改声音功能。

**技术排查与修复要求：**

1. **先验证系统通知通道。** 在扩展后台独立触发一次测试通知，排除 ChatGPT 网页检测链路；检查 `chrome.notifications.create` 的调用结果、错误，以及 Windows/Edge 的横幅、通知中心、“请勿打扰”等影响。
2. **改进回答完成检测。** 检查 `entrypoints/content.ts` 对现行 ChatGPT 页面结构的适配。采用多种生成/活动标记、必要的轮询兜底，以及回答真正完成的确认机制；不要仅把停止按钮暂时消失等同于最终完成。
3. **正确处理响应周期。** 长时间思考、工具调用与正文生成属于同一轮回答；过程中的短暂空隙不可提前通知。为每轮回答建立状态并去重，避免重复通知、页面刷新后的误通知。
4. **补充故障日志。** 能区分“未检测到完成事件”“内容脚本发送消息失败”“后台接收消息但通知创建失败”等情况，方便后续网页更新后的诊断。默认不需要在用户界面增加调试按钮。
5. **参考但不直接照搬**上游尚未合并的修复提案 [PR #3](https://github.com/Taragryen/chatgpt-notifier/pull/3)；任何方案均须结合当前页面与 Edge 实测验证。

**验收场景：**

| 场景 | 预期结果 |
| --- | --- |
| 普通简短回答完成 | 正常显示一次系统通知 |
| 长时间思考后完成 | 不在思考中途通知，最终完成时通知一次 |
| 使用工具/多阶段生成 | 不在中间阶段提前通知 |
| Edge 切换至其他标签页 | 回答完成仍可通知 |
| Edge 最小化但未关闭 | 回答完成仍可通知 |
| 同一轮回答多次更新/状态切换 | 不重复通知 |
| System Notification 关闭 | 不发出系统通知 |
| 刷新 ChatGPT 页面（没有新回答） | 不误触发通知 |
| Windows“请勿打扰”或通知权限被禁用 | 正确说明系统级限制，不将无横幅误判为扩展检测失败 |

**验证方式：** 优先在 Microsoft Edge + Windows 上实测上述场景；补充适当的自动化检查（如 TypeScript 类型检查、生产构建及可测试的状态逻辑）。CI 通过不等于系统通知实测通过。

## 三、范围限制

- 本次需求**仅包含名称调整、版本升级与系统通知修复**。
- 允许为系统通知修复调整必要的回答完成检测、后台通知及诊断代码；**不调整声音功能，也不改动其他无关功能**。
- 不进行无关重构、界面布局调整或 GitHub 仓库重命名。
- **本文仅记录需求；本次提交不实施程序修改，也不代表 v2.0.0 已发布。**
