## 二、故障现象与已确认的证据

在 Microsoft Edge + Windows 安装 v2.0.2，扩展面板中 **System Notification** 与 **Show Q&A Preview** 均已开启。新回答完成后 Windows 能弹出通知，但内容仍为 `ChatGPT has finished responding.`，没有“问/答”摘要。

### 2.1 扩展后台日志

用户通过 Console 核查：

- `chatgpt_notifier_system_notification_enabled: true`
- `chatgpt_notifier_qa_preview_enabled: true`
- 出现 `[ReplyNotice/background] Reply completion received`
- 诊断输出 `questionLength: 0, answerLength: 0`
- 出现 `[ReplyNotice/background] Notification created`

**判断：** 现有回答完成消息和 Windows 创建通知通道已运行；传到后台的两个预览摘要均为空。后台 `notificationText()` 在“提问摘要和回答摘要都为空”时按设计回退为通用英文提示。当前重点是内容脚本提取，不应再次盲目改动通知权限或重新实现后台消息机制。

### 2.2 ChatGPT 页面输入框只读检查

用户在尚未发送“你好”的情况下检查，结果如下：

| 选择器 | 找到元素 | 文本长度 |
| --- | --- | --- |
| `#prompt-textarea` | 否 | 0 |
| `textarea[name="prompt-textarea"]` | 否 | 0 |
| `[contenteditable="true"][data-placeholder]` | 否 | 0 |
| `[contenteditable="true"]` | 是 | 2 |

**判断：** 该次页面的可编辑输入框不符合 v2.0.2 `captureQuestionPreview()` 使用的三个选择器。需要兼容不带 `data-placeholder` 的 `contenteditable`，但不能无条件取页面中的任意可编辑元素。需同时验证实际发送事件发生时，文本尚未被清空。

### 2.3 ChatGPT 页面回答 DOM 只读检查

在回答完成后，使用已适配的助手轮次选择器：

`[data-turn-key]:has([data-conversation-role="assistant"])`

结果：

- 找到助手轮次容器；
- 该容器 `innerText` 长度为 **45**；
- 在该容器内，`.markdown`、`[data-testid="message-text"]`、`[data-message-content]`、`.prose` 的匹配数量均为 **0**。

**判断：** 轮次容器定位有效且其中存在可见文本，但当前 `extractAnswerPreview()` 正文候选选择器不命中。**尚未取得容器内部完整元素层级和文本归属证据**，不能把容器所有 `innerText` 或 `textContent` 直接当成回答，以免夹带标题、工具状态或思考细节。

## 三、最小修复目标

在**保留**现有回答完成确认、2.5 秒静默确认、响应周期去重、`CHATGPT_REPLY_DONE` 消息格式、后台隐私开关和通知点击回跳等逻辑的前提下：

1. 发送时能抓到本轮用户实际输入的文字，保存到**同一** `ReplyCycle.questionPreview`；无纯文本时优雅降级。
2. 最终完成后从**本轮**助手回复容器安全提取**回答正文**；在当前四个选择器无匹配时有受控兜底，排除非回答区域。
3. 保持提问最多约 **50** 字符、回答最多约 **100** 字符的限制；超过添加“……”。
4. 任一摘要为空不影响通知：允许显示“提问内容不可预览”或“ChatGPT 回答已完成”；二者都缺失时沿用通用提示。
5. 不在 Console 记录提问、回答全文或摘要内容；诊断只记录长度、是否命中及分支路径。
6. 不新增网络通信，不将聊天正文持久化到 `chrome.storage.local` 或 `chrome.storage.session`。

## 四、建议的代码修改（仅 `entrypoints/content.ts`）

### 4.1 修复 `captureQuestionPreview()` 的输入框选择

- 优先尝试当前已知输入框选择器。
- 额外支持不带 `data-placeholder` 的 `[contenteditable="true"]`，但**只在当前 ChatGPT 输入区/发送表单内**搜索，避免匹配聊天正文中的可编辑区域、设置面板或其他输入。
- 对 `textarea` / `input` 取 `value`；对 contenteditable 优先取 `innerText`，必要时回退到 `textContent`，随后归一化空白并截断。
- 捕获时间点保持在 `click` / `keydown` / `submit` 的提交前阶段；校验回车、发送按钮、输入法组合键的事件处理，避免输入框先清空而得到空文本。
- 保留现有 700 ms 提交去重；一次发送事件可能触发多个监听器，**不得重复建立快照**。如果后续活动标记引起同轮状态转换，应保留本轮问题，不从历史用户消息猜测。
- 附件、图片、空内容找不到有效文本时可留空，并通过既有回退行为通知。

建议在动手前先只读记录所选 `contenteditable` 的最近输入区祖先特征（如 form、发送按钮、role），据此限定搜索范围；不要把截图中单次存在的标签或 class 猜测成长期稳定结构。

### 4.2 修复 `extractAnswerPreview()` 的回答正文提取

- 保留现有 `ASSISTANT_SELECTOR`，继续从本轮 `assistant` 容器定位，保持 `baselineAssistant`、`cycleId` 的关联语义。
- 首先保留当前四种正文选择器；如果找不到候选或提取结果为空，再使用**限定在助手轮次内**的可见正文回退提取。
- 兜底提取应基于可见文本节点的遍历，而非直接使用整个轮次 `textContent`。过滤隐藏元素（包括 `hidden`、`aria-hidden`、`display:none`、`visibility:hidden`），并跳过按钮、toolbar、导航、标题角色标记、复制/反馈/分享操作、思考或推理详情、工具活动及折叠的细节区域。
- 当页面 DOM 无法可靠分离正文与思考/工具过程时，**宁可返回空摘要并使用“ChatGPT 回答已完成”**，也不把整轮文字强行加入可能出现在锁屏上的通知。
- 归一化空白，兼容段落、列表、行内代码、代码块，不拼接按钮/辅助文本，不采集历史轮次。
- 仅在现有 `completed` / `fallback` 终结条件成立后提取，不提前采集思考过程；异常应被局部捕获并返回空摘要，不能阻断 `notifyBackground()` 发送正常完成通知。

在实施兜底前，建议用只读 DOM 检查确认：回答正文位于助手轮次哪一层，是否有可区分于工具进程/思考详情的稳定容器，以及复制按钮是否属于该轮次；避免用一个全局宽泛选择器覆盖全部页面。

### 4.3 诊断但不泄露内容

可以仅在开发者工具中报告以下元数据：

- 本轮输入区是否找到、提交前捕获长度；
- 助手轮次是否找到、正文选择器命中数量；
- 采用“明确正文容器 / 安全回退 / 无法提取”哪一种路径；
- 最终发给后台的 `questionPreview.length`、`answerPreview.length`（**不打印正文**）。

不额外添加永久调试 UI、默认上传日志或后台存储聊天文本。

### 6.2 验收矩阵

| 场景 | 预期 |
| --- | --- |
| 两个开关均开启，发送“你好” | 收到一次通知，问题摘要不为空，回答摘要来自本轮正文 |
| 两个开关开启，连续两轮不同问题 | 两次通知分别匹配对应问答，不串轮、不重复 |
| 输入框只有 `[contenteditable="true"]` | 能在提交前捕获文本，适配 Enter 与按钮发送 |
| 新版助手轮次有可见回答文本而旧正文选择器均为 0 | 在过滤非正文后仍能提取回答，或安全降级 |
| 列表/代码/长内容 | 保留可读摘要，50/100 字符左右限长与省略号生效 |
| 长时间思考、工具调用、多阶段生成 | 不提前通知；不得泄露思考和工具状态 |
| 预览开关关闭、通知总开关开启 | 仍显示旧版通用通知，不含问答 |
| 通知总开关关闭 | 不创建系统通知 |
| 无文本提问、纯图片或附件 | 无异常、不吞通知，使用安全降级 |
| 刷新、切换会话、后台标签、多标签 | 不误触发，问答与来源会话正确关联 |
| 点击通知 | 仍能激活来源会话或安全降级 |
| 插件重载或旧历史通知 | 以重新加载后新生成的通知验收，不以旧通知中心记录判断 |

**最小通过证据：** 在后台诊断中 `previewEnabled=true`，且普通文本问答的 `questionLength > 0`、`answerLength > 0`；通知显示“问：… / 答：…”；同轮只发一次。对复杂场景须额外人工检查是否误包含非回答内容。
