## 二、背景与目标

目前 `feature/v2.0.4` 已实现通知内的**“清空全部”**按钮，点击后可批量清理当前答讯扩展可管理的通知。实机截图显示只有一个底部操作按钮，缺少“只关闭当前这一条、但不跳转 ChatGPT”的显式入口。

期望每条答讯通知包含两个操作按钮，尽量并排显示：

```text
答讯 · ReplyNotice
问：你好
答：你好！今天有什么需要我帮忙的？

[      关闭      ] [     清空全部     ]
```

- **左侧按钮：关闭** —— 只关闭当前通知，不打开 ChatGPT。
- **右侧按钮：清空全部** —— 清除答讯扩展当前可管理的全部通知，不打开 ChatGPT。
- **点击通知正文：** 沿用 v2.0.3 已实现的“打开对应 ChatGPT 会话并清除当前通知”。
- **系统右上角 X：** 继续只关闭当前通知，不跳转，不批量清理。

### Windows / Edge 样式约束

Chrome/Edge 扩展通知支持两个操作按钮，数组顺序定义按钮索引，但实际排版由 Edge 和 Windows 的系统通知界面决定。

**希望两个按钮左右并排、宽度各占约 50%；但不能通过 `chrome.notifications` API 强制规定布局、宽度、始终可见或准确顺序在所有系统上的呈现。** 验收重点是两个操作及其语义正确，并在当前用户 Edge/Windows 环境中实测视觉效果；不以“精确 50% 宽”作为硬性标准。

## 四、具体实施方案（文档方案，不在本次提交中执行）

### 4.1 把原来的单按钮改成双按钮

文件：`entrypoints/background.ts`，`chrome.notifications.create({...})` 配置。

**修改前：**

```typescript
buttons: [{ title: '清空全部' }],
```

**修改后：**

```typescript
buttons: [
  { title: '关闭' },      // buttonIndex === 0
  { title: '清空全部' },  // buttonIndex === 1
],
```

继续保留 `type: 'basic'`、`requireInteraction: true`、图标、标题、问答摘要、通知优先级及通知创建回调；无需添加新权限或新依赖。

### 4.2 增加“关闭当前通知”，迁移“清空全部”的索引

文件：`entrypoints/background.ts`，现有 `chrome.notifications.onButtonClicked.addListener`。

**目前：** `buttonIndex === 0` 直接进入 `getAll() + clear()` 批量清理分支。

**调整为：**

```typescript
chrome.notifications.onButtonClicked.addListener((notificationId, buttonIndex) => {
  if (buttonIndex === 0) {
    // 仅 chrome.notifications.clear(notificationId)
    // 清除成功或确认该通知已不存在时，清理本条来源映射
    // 不跳转 ChatGPT、不清理其他通知
    return;
  }

  if (buttonIndex === 1) {
    // 复用 v2.0.4 已有的 getAll() + clear() 全部清理逻辑
    // 保留部分失败继续处理、来源映射清理与并发保护
    return;
  }

  // 未知索引：不执行操作
});
```

这段为**逻辑示意，不是可直接替换的完整函数**。实施时应保留当前 `buttonIndex === 0` 分支下已写好的完整批量清理实现，**只调整入口为索引 1**，不要复制或重写 `getAll()` 遍历、异步计数和异常处理。

“关闭当前通知”分支的明确要求：

1. 直接对当前 `notificationId` 调用 `chrome.notifications.clear(notificationId)`；不得调用 `getAll()` 批量清空。
2. 检查 `chrome.runtime.lastError` 及 `wasCleared`；成功清除或确认该 ID 已不存在时，再删除 `NOTIFICATION_ORIGIN_PREFIX + notificationId` 这一条来源映射。
3. 对 `clear()` 失败且该通知仍存在的情况，不提前丢弃原会话来源映射；记录简洁错误日志。
4. 与现有 `onClosed` 的单条清理事件可能同时发生，存储删除应安全幂等；不能影响其他通知。
5. 如果同一通知的正文点击处理 `onClicked` 已开始读取来源映射，要尊重 `pendingNotificationClicks`，避免提前清理导致错误跳转。
6. 关闭按钮**不调用** `openChat()`、`chrome.tabs.*`、`chrome.windows.*`，不弹二次确认，不发送额外通知。

“清空全部”分支的明确要求：

- `buttonIndex === 1` 才执行现有的 `chrome.notifications.getAll()` 批量清理。
- 保留 v2.0.4 的“单次快照、逐条清理、部分失败继续、来源映射同步清理、并发点击保护”逻辑。
- 只处理答讯本扩展可管理的通知；不清理 Windows 全部通知或其他应用通知。
- 清空完成后新产生的回答提醒仍可正常显示。

### 4.3 保留正文点击和系统关闭按钮行为

| 触发入口 | 行为 | 是否打开 ChatGPT | 清理范围 |
| --- | --- | --- | --- |
| 通知正文任意可点击区域 | 跳转到对应会话 | 是 | 当前这一条 |
| **左侧“关闭”（索引 0）** | 直接关闭 | 否 | 当前这一条 |
| **右侧“清空全部”（索引 1）** | 批量清空 | 否 | 当前扩展可管理的全部通知 |
| 右上角系统 X | 原生关闭 | 否 | 当前这一条 |

两个操作按钮的事件应由 `onButtonClicked` 处理，不应进入原有的 `onClicked` 正文跳转路径；如果 Edge 平台表现有差异，应在实机验证后采用最小兼容性处理。

## 五、测试与验收

开发完成后在 `feature/v2.0.4` 执行 `pnpm build`，重新加载 Edge 本地扩展，再测试：

| 测试场景 | 预期结果 |
| --- | --- |
| 生成一条通知 | 可找到“关闭”“清空全部”两个按钮；实际排版依系统 |
| 点击左侧“关闭” | 仅当前通知消失，**不会打开 ChatGPT** |
| 生成 3 条通知并点击其中一条的“关闭” | 其余两条不受影响 |
| 生成 3 条通知并点击右侧“清空全部” | 尝试清理扩展 `getAll()` 返回的全部可管理通知，**不会打开 ChatGPT** |
| 点击正文 | 跳转对应 ChatGPT 会话，只清理当前通知 |
| 点击右上角 X | 只关闭当前通知、不跳转、不清空其他通知 |
| 清空或单条关闭完成后 | 仅相关通知来源映射被清理，无无关存储数据误删 |
| 部分清理失败或通知已自动消失 | 不报未处理异常、不影响其他通知；按现有安全策略处理来源映射 |
| 多标签页、多条连续回复、快速点击 | 不串会话、不重复批量清理、不发生错误跳转 |
| Windows 通知中心操作 | 验证按钮仍可操作及两种动作；接受平台显示限制 |
| 清理之后又收到新回答 | 提醒继续按原逻辑正常弹出 |
| 版本验证 | `wxt.config.ts`、`package.json`、构建 `manifest.json`、Edge 页面均仍是 **2.0.4** |

**系统限制**：`chrome.notifications.getAll()` 只能管理该扩展当前可见的通知集合，不保证清空 Windows 通知中心中的所有历史条目；不要求强制横向各占精确 50%。
