# 答讯 · ReplyNotice — v2.0.1.1 版本号同步修改方案

## 一、目的与范围

本文件为 **v2.0.1 的补充修改方案**（文档编号：v2.0.1.1），用于补全上一次 DOM 适配方案遗漏的版本号修改步骤。

- 仓库：`LynFrost/Daxun`
- 开发分支：`feature/v2.0.1`
- 对应功能需求：`docs/v2.0.1-ChatGPT新版DOM适配与通知修复.md.md`（仓库现有文件名）
- **目标插件版本：v2.0.1（不是 v2.0.1.1）**
- 本文件**只记录方案，不实施代码更改**。
- 限制：只同步两个必要的版本配置；不改动 DOM 检测、通知逻辑、声音功能、插件布局和其他文件。

## 二、实际问题

DOM 识别兼容修复已经写入 `entrypoints/content.ts`，但 v2.0.1 开发分支中的两处版本配置依然是 `2.0.0`，所以执行 `pnpm build` 后，Edge 安装的扩展仍显示 v2.0.0。

版本号不会随 Git 分支名或重新构建自动增加；需要显式同步配置。

## 三、需要修改的全部文件

### 1. `wxt.config.ts`（原第 6 行）

**原代码：**

```typescript
version: '2.0.0',
```

**改为：**

```typescript
version: '2.0.1',
```

用途：WXT 用此处的 `manifest.version` 生成浏览器扩展的 `manifest.json`，Edge 扩展管理页面展示该版本。

### 2. `package.json`（原第 3 行）

**原代码：**

```json
"version": "2.0.0",
```

**改为：**

```json
"version": "2.0.1",
```

用途：同步项目包的版本元信息，避免与扩展实际版本不一致。

> 行号以本方案编写时的 `feature/v2.0.1` 文件为准。以字段和值定位修改，不依赖行号永久不变。

### 无须额外修改的文件

- `entrypoints/popup/App.ts` 已通过 `chrome.runtime.getManifest().version` 动态显示版本号（前缀 `v`），**不需要修改**。
- 不需要为此次版本号同步而修改 `background.ts`、`content.ts`、`README.md`、其他源文件或工作流。
- 不手工改写 `pnpm-lock.yaml`；如依赖工具意外生成额外差异，应先检查原因，避免带入无关文件。

## 四、构建与安装验证

在项目根目录、`feature/v2.0.1` 分支执行：

```powershell
pnpm build
```

构建完成后，检查生成的扩展清单：

```powershell
Get-Content .output\chrome-mv3\manifest.json |
  ConvertFrom-Json |
  Select-Object name, version
```

**预期输出：**

```text
name                  version
----                  -------
答讯 · ReplyNotice    2.0.1
```

然后进入 Edge 的 `edge://extensions`：

1. 确认加载的是本地 `.output/chrome-mv3`，而不是旧商店插件；暂时禁用其他答讯/ChatGPT Notifier 实例。
2. 对本地扩展点击**重新加载**。
3. 确认扩展详情显示 **版本 2.0.1**。
4. 打开扩展面板，确认底部显示 **v2.0.1**。
5. 刷新已打开的 `chatgpt.com` 页面，再验证此次 DOM 适配的回答完成通知功能。

## 五、验收标准

- `wxt.config.ts` 的 `manifest.version` 为 `2.0.1`。
- `package.json` 的 `version` 为 `2.0.1`。
- 构建成功，产物 `manifest.json` 的 `version` 为 `2.0.1`。
- Edge 管理页显示 2.0.1，插件面板显示 v2.0.1。
- 版本配置同步仅涉及上述两个文件；功能是否修复成功仍依照 v2.0.1 DOM 适配文档单独进行实测验收。
