# 答讯 · ReplyNotice — v2.0.3 通知停留与点击清除优化

## 一、版本信息与范围

- 仓库：`LynFrost/Daxun`
- 开发分支：`feature/v2.0.3`（已存在，以 `main` 的 v2.0.2 为基线）
- 基线版本：**v2.0.2**
- 目标插件版本：**v2.0.3**
- 需求名称：**通知停留与点击清除优化**
- 目标平台：Microsoft Edge + Windows
- 本次操作：**新增本需求文档并同步两个版本号配置**；以下通知行为仍是待开发、待实测的方案，不代表功能已经完成。

## 二、目标行为

保持现有答讯的回答完成检测、系统通知、问答摘要预览、隐私开关、点击返回原对话、去重和提示音等功能；仅优化通知显示和点击关闭：

1. ChatGPT 回答完成后，继续使用现有 Windows/Edge 原生系统通知。
2. 请求尽可能长时间保留桌面通知横幅，不再按默认时长过快消失。
3. 点击通知**正文可点击区域的任意位置**，打开其对应的 ChatGPT 会话，并主动清除**这一条**通知。
4. 点击系统提供的 **X/关闭** 控件时，仅关闭通知，不打开 ChatGPT。
5. 对于没有及时点击、被 Edge 自动收纳至 Windows 通知中心的通知，允许用户之后从通知中心点击；仍应尽量准确跳到对应会话。
6. 多条通知独立，不要在点击一条时清除其他条。

### 系统边界（明确不承诺）

- 采用**第一种方案**：纯浏览器扩展 + Windows 原生通知；**不开发 Windows 辅助进程、不创建自定义桌面悬浮窗**。
- `chrome.notifications` 的 `requireInteraction: true` 是浏览器的停留请求，而不是越过 Edge/Windows 限制的强制永久置顶能力。
- Microsoft Edge 从 Edge 85 起曾公布：即使设置 `requireInteraction`，Windows 桌面横幅也可能约 **25 秒**后自动收纳至通知中心。此行为以当前用户系统实测为准，不把“永久显示”或“准确显示 25 秒”作为验收标准。
- Windows 请勿打扰、关闭通知权限、通知中心设置、锁屏、用户点击 X、系统自动清理等情形，扩展不能保证横幅显示或通知永久保留。
- “点击任意位置”专指**通知正文/卡片的可点击区域**；系统关闭按钮及系统菜单不属于这一范围。

参考：
- Chrome Notifications API：`https://developer.chrome.com/docs/extensions/reference/api/notifications`
- Microsoft Edge 原生通知行为说明：`https://blogs.windows.com/msedgedev/2020/07/23/reducing-distractions-quiet-notification-requests/`

## 三、代码修改方案（功能代码暂不实施）

### 需求 1：延长通知横幅停留

文件：`entrypoints/background.ts`

位置：`createSystemNotification()` 的 `chrome.notifications.create({...})`，当前约 **151–157 行**。

当前片段：

```typescript
chrome.notifications.create({
  type: 'basic',
  iconUrl: chrome.runtime.getURL('logo.png'),
  title: payload?.title || '答讯 · ReplyNotice',
  message: payload?.message || 'ChatGPT has finished responding.',
  priority: 1,
}, (notificationId) => {
  // 保留当前通知创建回调
});
```

拟在选项对象内增加**一行**（其他字段保持不变）：

```typescript
requireInteraction: true,
```

注意：无需改动通知标题、正文、优先级、权限检查、成功回调或测试通知通道。当前测试通知如果也使用此函数，延长停留参数会同时对测试通知生效。

### 需求 2：点击通知正文后，清除这一条通知

文件：`entrypoints/background.ts`

位置：现有 `chrome.notifications.onClicked.addListener`（当前约 **88–124 行**）。

- 复用已经存在的 `notificationId`、`chrome.storage.session` 来源映射、标签激活/打开与窗口聚焦逻辑。
- 点击时调用 `chrome.notifications.clear(notificationId)`；只清除当前 ID，不能调用批量清空或覆盖其他通知。
- **顺序尤其重要**：先读取/复制该 ID 的有效 `NotificationOrigin`（或兜底 URL），再清除通知；因为主动 `clear` 可能触发 `onClosed`，若先清理就可能丢失原对话映射。
- 在取得必要来源后清除该条通知，并继续执行现有跳转逻辑；即使通知已被系统自动关闭，`clear` 返回不存在/false 也不能阻止正常跳转。
- 保留原有标签已关闭、页面已跳走、多标签页对应关系、失效来源兜底等处理。
- 仅对点击事件跳转；不要把用户点击 X 的 `onClosed` 当作 `onClicked`。
- 清除操作应检查 `chrome.runtime.lastError`，必要时记录简洁日志，不让无关清理失败影响跳转。

### 需求 3：从 Windows 通知中心点击仍可跳转

文件：`entrypoints/background.ts`

位置：`onClicked`、`onClosed`、`rememberOrigin` 和 `pruneOrigins`，目前约 **52–78、88–130 行**。

现有设计：
- 来源映射保存在 `chrome.storage.session`，每个 `notificationId` 对应原标签、URL 和创建时间。
- `onClosed` 会立即删除该通知的来源映射。
- 当前 `ORIGIN_TTL_MS` 为 **24 小时**，`MAX_ORIGINS` 为 **100**。

潜在风险：如果 Edge 将桌面横幅收纳到通知中心时也触发某种关闭事件，可能导致来源映射在用户点击通知中心之前就被删除。**这是待实测风险，不预先断言 Edge 一定会如此。**

实施要求：
1. 实测桌面横幅消失、通知转入通知中心时 `onClosed` 是否触发，及 `chrome.notifications.onClicked` 是否仍会触发。
2. 仅当通知确实被关闭/清除、不再可点击时，才应清理其来源映射；不能把“横幅不显示了”等同于“通知已不存在”。
3. 若当前 `onClosed` 行为正常，不必额外复杂化实现；若会提前丢失映射，应采用能够区分实际通知生命周期的最小修正方案，同时避免泄漏和无上限积累。
4. 继续使用现有受信任的 `https://chatgpt.com/` URL 校验；勿允许任意地址跳转。
5. 本次不扩大存储范围，不保存问答正文。保留 **24 小时 / 100 条**映射限制；超时、浏览器重启或映射被清理后，允许降级到 ChatGPT 首页，不能承诺仍精确打开旧会话。

### 需求 4：保持已有功能不回归

- 仍尊重系统通知总开关，关闭时不发通知。
- 保留“通知显示问答内容”隐私开关与原有摘要格式、截断逻辑。
- 保留每轮只发一次的去重机制；不可为追求常驻而定时反复创建相同通知。
- 保留提示音功能与原有 `CHATGPT_TEST_NOTIFICATION` 测试入口。
- 不改动 `entrypoints/content.ts` 的回答完成检测状态机。
- 不增加 Windows 托盘程序、自定义悬浮窗、计划任务、系统设置强制修改或额外依赖。

## 五、测试步骤与验收矩阵

在 `feature/v2.0.3` 中完成功能开发后：

1. 执行 `pnpm build`，构建成功。
2. 检查 `.output/chrome-mv3/manifest.json`：`name` 为“答讯 · ReplyNotice”，`version` 为 `2.0.3`。
3. Edge `edge://extensions` 重新加载本地构建的扩展，刷新 ChatGPT 页面，确认扩展详情及面板版本均为 **v2.0.3**。
4. 依下表实测（以用户实际 Edge/Windows 行为为准）：

| 场景 | 预期结果 |
| --- | --- |
| 提交普通问题、正常回答完成 | 仅弹出一条通知；问答摘要/通用文案按原设置显示 |
| 通知出现后立即点击正文 | 跳到对应会话，该条通知被清除 |
| 点击通知卡片内不同正文位置 | 均触发与正文点击一致的行为（排除 X/系统菜单） |
| 点击 X | 关闭该通知，不跳转 ChatGPT |
| 通知出现后不点击，等待 30 秒及更久 | 记录实际横幅停留时长；允许系统自动收纳，**不要求永久停留** |
| 通知转入 Windows 通知中心后点击 | 能触发跳转并清除；正常来源映射仍存在时准确返回原会话 |
| 连续收到两条不同会话的通知 | 点击其中一条只清除该条，不影响另一条的点击关联 |
| 同一会话连续两轮回答 | 每轮仅通知一次；旧通知不因新通知创建而被错误清除 |
| 来源标签已关闭或已导航到其他页面 | 打开受信任的原会话 URL；来源无效时安全降级 |
| 来源已超过 24 小时、超过容量上限或浏览器重启 | 允许跳转到 ChatGPT 首页；不得打开不受信任地址 |
| 关闭系统通知总开关 | 不创建通知 |
| 开关问答摘要预览 | 分别正确显示通用文案 / 问答摘要 |
| Edge 通知权限关闭、Windows 请勿打扰 | 符合平台行为，不死循环重试、不影响页面 |
| 扩展测试通知 | 仍能用测试消息验证通知通道和延长停留参数 |

**重点观察**：横幅自动收纳后，通知是否还可点击、`onClosed` 的触发时机，以及来源映射是否仍有效。不要将“已调用 `notifications.create`”误认为“Windows 必然已经弹出横幅”。
